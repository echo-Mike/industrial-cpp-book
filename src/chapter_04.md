# Глава 4: Ввод и вывод в C++

В данной главе мы поговорим об окружении большинства программ на C++ и взаимодействии с ним.

## Ввод и вывод типы и виды

Ввод и вывод традиционно являются важными темами для любого языка программирования. Так первым руководством по работе с языком часто является вывод данных \- программа “Здравствуй мир”. Ввод и вывод являются частью более общего направления \- работы с окружением программы.  
Для типичной программы на C++ актуальные следующие виды работы с окружением:

* Работа с аргументами командной строки  
* Работа с переменными окружения  
* Консольный ввод/вывод  
* Файловый ввод/вывод  
* Файло-подобный ввод/вывод  
* Работа с графической подсистемой и пользовательским вводом

Этот набор актуален для большинства программ на C++, но не для всех. Так для встраиваемых систем консольный ввод вывод может быть организован через шины передачи данных, например UART, файлового вывода может не быть как такового.

### Аргументы командной строки

В C++ определено, что аргументы командной строки передаются непосредственно в ключевую функцию программы `main()` в виде C массива указателей на нуль-терминированные строки.Однако также существуют методы получения аргументов, предоставляемые отдельными платформами, например для того, чтобы получить аргументы в виде строк широких символов в Windows.  
C++ не предоставляет в стандартной библиотеке методов обработки аргументов, однако для этого написано много сторонних библиотек. Например в библиотеке Boost есть `boost::program_options`, а на платформах POSIX функции `getopt()` и `getoptlong()`.

### Переменные окружения

В современной разработке, а особенно для бекэнд приложений, данный механизм играет значение базовой настройки и передачи секретов. В POSIX совместимых системах через переменные окружения очень любят настраивать библиотеки, которые могут исполняться до main() или неявно, такие как системные аллокаторы и библиотеки поддержки кодогенерации.  
В C++ установлен стандартный способ получить значение переменной окружения через функцию `std::getenv()`.

### Графическая подсистема и пользовательский ввод

Для разработки под персональные компьютеры актуален вопрос взаимодействия с графической подсистемой и пользовательским вводом. В стандарте C++ на данный момент нет общих методов для такой работы, однако она хорошо реализуется с использованием сторонних библиотек.

### Файло-подобный ввод/вывод

Представляет большой интерес с точки зрения программиста, так как благодаря POSIX мы имеем общий “интерфейс файла” для целого множества сущностей, таких как пайпы, сокеты, терминал консоли, устройства и, собственно, файлы. Все они реализуют подмножество операций, доступное для файла на диске, ввиду чего образуется слой универсальной абстракции.  
В данной главе мы будем рассматривать возможность C++ по работе именно с этим слоем абстракции.  

## Ввод/вывод в стиле С

Ввод/вывод в стиле С это коллективное название для набора функций стандартной библиотеки C++, которые имеют те же имена и семантику, что и функции стандартной библиотеки С.

### Дизайн ввода/вывода в стиле С

Ввод/вывод в стиле С отличаются следующими аспектами дизайна:

* Данный функционал реализуется в С стиле классов, где существует структура без методов и набор статических функций, принимающих первым параметром данную структуру, реализующий операции.  
* Объекты ОС, доступные для ввода/вывода представлены объектами типа указатель на `std::FILE`.  
* Для работы доступны следующие режимы открытия объекта ввода/вывода ОС:  
  * Для чтения \- обычно НЕ создает объект, если таковой не находится в ОС.  
  * Для записи \- обычно создает объект, если таковой не находится в ОС.  
  * Для записи в конец \- отличается от режима для записи тем, что не удаляет контент объекта ОС при открытии.  
  * Для чтения и записи \- объект открывается для чтения и для записи, при этом обычно создает объект, если таковой не находится в ОС.  
  * Для чтения и записи в конец \- отличается от режима для чтения и записи тем, что не удаляет контент объекта ОС при открытии.  
* Выделены три статические переменные, использование функций вывода на которых, эквивалентно взаимодействию со стандартными потоками ввода (`stdin`), вывода (`stdout`) и вывода ошибок (`stderr`).  
* Опциональный буферизированный ввод/вывод.  
* Предоставляются два вида функций ввода вывода, для для узких строк с типом `char*` и широких строк с типом `wchar_t*`.  
* Предоставляется возможность использовать три набора функций ввода/вывода:  
  * Прямой ввод/вывод;  
  * Неформатированный ввод/вывод;  
  * Форматированный ввод/вывод:  
* Обработка ошибок выражается в виде возврата специального результата из функции и последующем вызове функций проверки состояния ошибки.  
* Функции неформатированного ввода вывода определены в двух видах:  
  * `<имя функции>` \- такая функция оперирует над стандартными потоками ввода/вывода `stdin`/`stdout`;  
  * `f<имя функции>` \- такая функция оперирует над файлом, переданным первым аргументом;  
* Функции форматированного ввода/вывода доступны в трех или четырех вариантах:  
  * `<имя функции>` \- такая функция оперирует над стандартными потоками ввода/вывода `stdin`/`stdout`;  
  * `f<имя функции>` \- такая функция оперирует над файлом, переданным первым аргументом;  
  * `s<имя функции>` \- такая функция оперирует над регионом в памяти, называемым буфером, передаваемым в функцию;  
  * `sn<имя функции>` \- тоже самое что `s<имя функции>f`, только принимает дополнительный аргумент максимальной длины вводимой последовательности.

### Практика использования ввода/вывода в стиле С

#### Безопасность ввода/вывода в стиле С

Данное API плачевно известно тем, что именно через него реализуются многие уязвимости в приложениях на С и C++. Такие API принято называть подверженным ошибкам (error-prone). На это есть несколько причин:

* Работа с ошибками затруднена. Для этого есть несколько предпосылок:  
  * Полезные значение и значения, обозначающие ошибку, передаются как значения одного и того же типа. Такой подход приводит к разбуханию кодовой базы, что натурально противодействует желанию типичного программиста писать краткий код.  
  * Разные типы возвращаются из разных функций, что приводят к отсутствию единых ошибочных значений и необходимости обрабатывать ошибки уникально для каждого набора функций.  
  * Возвращаемые значения имеют числовой тип, а ошибки отрицательное или нулевое значение, что приводит к ошибке складывания возвращаемого значения с буферной переменной.  
* Форматированный вывод имеет опасные квалификаторы  
  * Особой опасностью обладает квалификатор `%n` его особо часто используют для эксплуатации уязвимостей. Данный квалификатор приводит к модификации памяти при чтении для форматирования, что является хорошим гаджетом для составления эксплоита.  
* Форматированный вывод не использует проверку типов аргумент  
  * Форматированный вывод полностью полагается на верность описателя формата в отношении переданных аргументов, так как использует сигнатуру функции с переменным числом аргументов. Это приводит к тому, что переданный в функцию аргумент может по типу не совпадать с выделенным данному аргументу классификатором формата. Это приводит к чтению памяти вне ожидаемых границ, что помогает например атакам против ASLR.  
* Функциями ввода/вывода очень легко обратиться вне границ буфера  
  * Изначальный дизайн функций в POSIX был достаточно давно признан небезопасным  
  * Для использования безопасных функций программисту требуется дополнительное обучение  
  * Небезопасные функции остаются доступными в стандартной библиотеке, так как множество программ продолжает от них зависеть

#### Зависимость формата от локали

Львиную долю проблем с производительностью ввода/вывода в C++ обычно относят к неявной работе API ввода/вывода с локалями, следствия чего мы увидим далее. Локаль это сущность, обычно выражаемая набором функций проверок, преобразований и форматирования, которая отвечает за локализацию (**l10n**) и интернационализацию (**i18n**) работы со строковым представлением данных в C++.  
Функции локали используются при форматировании времени, денег, чисел, кавычек и других синтаксических конструкций записи натурального языка.  
В API ввода/вывода в стиле С используется глобальная локаль, как она определена в языке С. Для ее изменения используются функция `std::setlocale` и тип `std::lconv`. Также С локаль неявно используется в функциях проверки принадлежности знака к группе (`std::is*` и `std::isw*`).  
Проблемы с производительностью возникают из\-за:

* Множества не встраиваемых вызовов при форматировании.  
* Глобальности объекта локали.  
* Проблем с гонками при смене локали.

#### Типы сырых строк в C++

В описании дизайна уже упоминалось, что функции ввода/вывода дублируются для узких и широких символов. Однако это не единственные типы строк, которые поддерживаются в C++. Строки, которые представляются в памяти набором символов, с завершающим нулевым символом, называются сырыми строками (null-terminated strings или raw strings). C++ определяет три типа сырых строк:

* Нуль-терминированные байтовые строки (NTBS, null-terminated byte strings) \- это байтовые последовательности, которые заканчиваются нулевым байтом, их кодировка не определена, но считается что каждый символ соответствует одному байту.  
* Нуль-терминированные широкие строки (NTWS, null-terminated wide strings) \- это последовательности `wchar_t`, которые заканчиваются нулевым значением `wchar_t`, и представляются в кодировке, зависимой от операционной системы. Считается что каждый символ закодирован одним значением `wchar_t`.  
* Нуль-терминированные многобайтовые строки (NTMBS, null-terminated multibyte strings) \- это байтовые последовательности, имеющие кодировку, т.е. каждый символ в которых может занимать более одного байта, также как и символ нуль-терминированности.

API стандартной библиотеки по работе с разными видами нуль-терминированных строк доступно по следующим ссылкам:

* Нуль-терминированные байтовые строки [https\://en.cppreference.com/w/cpp/string/byte](https://en.cppreference.com/w/cpp/string/byte)  
* Нуль-терминированные широкие строки [https\://en.cppreference.com/w/cpp/string/wide](https://en.cppreference.com/w/cpp/string/wide)  
* Нуль-терминированные многобайтовые строки [https\://en.cppreference.com/w/cpp/string/multibyte](https://en.cppreference.com/w/cpp/string/multibyte)  

В рамках данной книги имеет смысл рассмотреть только общие шаблоны работы и частные функции имеющие широкое распространение в кодовых базах.

##### Наиболее важные функции и шаблоны работы при манипуляции сырыми строками

###### Функции байтовой манипуляции

Набор функций `std::memcmp` (трехстороннее сравнение байт), `std::memset` (установка значения региона байт), `std::memcpy` и `std::memmove`, хоть и относятся к функциям манипуляции с нуль-терминированными байтовыми строками, но приобрели большое значение и вне рамках данного направления для работы с сырой памятью, что в промышленных задачах далеко не редкость.  
Тут стоит отметить разницу между алгоритмами копирования памяти  `std::memcpy` и `std::memmove`:

* При использовании `std::memcpy` на пересекающихся промежутках памяти может привести к неопределенному поведению, ввиду того, что реализация `std::memcpy` обычно очень оптимизирована и может приводить к ошибкам на уровне процессора.  
* Использование `std::memmove` определено для пересекающихся промежутков, но алгоритм может быть намного медленнее чем `std::memcpy`.

###### Задача разбора строк

Задача разбора (парсинга) строк состоит в изменении репрезентации данных из строковой в бинарную. Данную задачу решают в двух стилях, стиле С и стиле C++. В данном пункте мы рассматриваем стиль С. Для парсинга строк часто используют функции из набора (`<тип>` \- `str`, для байтовых и `wcs` для широких строк):

* `std::<тип>chr` \- Поиск первого вхождения символа  
* `std::<тип>rchr` \- Поиск последнего вхождения символа  
* `std::<тип>spn` \- Определить длину префикса, состоящего только из переданного набора символов  
* `std::<тип>cspn` \- Определить длину префикса, состоящего только НЕ из переданного набора символов  
* `std::<тип>pbrk` \- Поиск первого вхождения символа из переданного набора символов  
* `std::<тип>str` \- Поиск первого вхождения переданной подстроки  
* `std::<тип>tok` \- Поиск начала следующего “токена”, в строке где “токены” разделены символами из переданного набора символов

Помимо функций из данного набора для парсинга используются функции форматированного ввода где это уместно. Уместность можно определять следующим образом \- если парсится некая структура с известным набором полей или форматом, то лучше использовать функции форматированного ввода, иначе формат динамический или не определенный (например парсинг языка в AST), тогда имеет смысл использовать оба набора функций совместно.

###### Работа с кодировками

На момент C++23 более простого способа, чем тот, о котором будет рассказано далее, работы с кодировками строк, используя только стандартную библиотеку, не предусмотрено. Крайне рекомендуется использовать сторонние библиотеки при работе с локализованными строками, так как способ, предлагаемый стандартной библиотекой, не является эталоном дизайна.  
В отличии от других языков, например, таких как Golang, где работа с байтами и символами строго разделена системой типов, в C++ исторически был выбран библиотечный подход, и на данный момент он определен в стиле С.  

> [!NOTE]
> Отвлечение:
> **Стиль С**, это когда в дизайне API не используются классы и методы, а используются структуры и свободные функции.  

Данный подход и API стандартной библиотеки относятся как к различным кодировкам текстовой информации, так и к универсальными кодировкам семейства UTF.  
C++ *НЕ предоставляет* функций прямой работы с многобайтовыми символами в произвольной кодировке. Для работы с такими строками требуется привести их широким символам, или строкам в кодировках семейства UTF.

###### *Алгоритм работы со строкой в произвольной кодировке*

Алгоритм работы со строкой в произвольной кодировке следующий:

* Если строка получена из функции, передающей ее в представлении `wchar_t*`, то сразу можно использовать функции работы с широкими строками, иначе  
* Строка передана в мультибайтовой кодировке, тогда  
* Если кодировка соответствует UTF-8, UTF-16 или UTF-32, то  
  * Использовать функции конвертации `std::mbrtoc8`, `std::mbrtoc16` и `std::mbrtoc32` для конвертации в сырые строки UTF,  
  * Использовать специализации шаблона `std::basic_string` (`std::u8string`, `std::u16string`, `std::u32string`)  для работы со строками, иначе  
* Установить С локаль согласно кодировке строки  
* Конвертировать многобайтное представление строки в представление строки с широкими символами `wchar_t`, используя функцию `std::mbsrtowcs`  
* Использовать для работы с широкой строкой функции в стиле С или специализацию шаблона `std::basic_string` (`std::wstring`) для широких строк.

Большими недостатками данного API являются:

* Легкость в допущении ошибки  
* Зависимость от глобальной локали

## Библиотека поточного ввода/вывода

На смену стилю С, который все же часто используется в приложениях на C++, пришла часть стандартной библиотеки C++, под названием библиотека поточного ввода/вывода.

### Дизайн библиотеки поточного ввода вывода

В основании библиотеки потокового ввода/вывода стоят следующие принципы:

* Поток (stream) \- это объект, абстрагирующий нижележащую сущность, также как `std::FILE`. У потока, в зависимости от типа, могут быть операции ввода и/или вывода.  
* Для задания свойств потокам используется иерархия наследования.  
* Все классы иерархии являются шаблонными с параметрами, определяющими тип символов (как в строках) и определенный набор операций над символами, такие как сравнение и поиск.  
* Два объекта контролируют работу с потоком:  
  * Сам объект **потока**, ответственный за форматирование.  
  * Объект **буфера потока**, который отвечает за буферизацию ввода/вывода и прямое взаимодействие с объектом ОС.  
* **Буфер потока** определяет сущность, над которой оперирует поток.  
  * Именного данный класс нужно расширять пользовательскими типами путем наследования, если требуется поддержать новый тип устройства ввода/вывода.  
  * В стандартной библиотеке предоставляются буферы потока:
    * `std::basic_filebuf` для файлового ввода/вывода
    * `std::basic_stringbuf` для ввода/вывода в строковый класс стандартной библиотеки C++
    * `std::basic_spanbuf` (C++23) для ввода/вывода поверх произвольной последовательности символов  
  * Связь **потока** и **буфера потока** производится через метод потока `rdbuf()`  
* Объект потока ответственен за:  
  * Параметры форматирования  
  * Информацию о состоянии ввода/вывода и обработку ошибок  
  * Менеджмент позиции в потоке  
  * Операции форматированного и не форматированного ввода/вывода  
  * Связывание с локалью  
* Ввод/вывод в поток помимо явных функций членов объекта потока, также доступен через точку расширения `operator>>()` для вывода из потока  и `operator<<()` для ввода в поток.  
* Установка параметров формата вывода может быть выполнена как через явные методы потока так и через использование *манипуляторов ввода/вывода*, передаваемых через `operator>>()` и `operator<<()`.  
  * Второй вариант намного более популярен, так как позволяет связать в единую цепочку вызовов изменения формата и ввод/вывод, что приводит к красивому синтаксису

```c++
std::cout << std::hex // Манипулятор вывода чисел в 16-ричной системе
          << "showbase: " << std::showbase << 42 << '\n'
          << "noshowbase: " << std::noshowbase << 42 << '\n';
// Вывод:
//  showbase: 0x2a
//  noshowbase: 2a
```

В полной форме весь API данной библиотеки можно посмотреть по ссылке [https\://en.cppreference.com/w/cpp/io\#Stream-based\_I.2FO](https://en.cppreference.com/w/cpp/io#Stream-based_I.2FO). Далее же детально рассмотрим некоторые элементы дизайна библиотеки потоков ввода/вывода с которыми приходится часто встречаться или которые могут быть не очевидными при их использовании.

#### Элементы дизайна библиотеки потокового ввода/вывода

##### Предопределенные типы и переменные

Также как и API в стиле С библиотека поточного ввода/вывода предоставляет предопределенные переменные для работы со стандартными потоками ввода вывода (и их аналоги для широких символов вида `std::w<имя>`):

* `std::cin` для стандартного потока ввода.  
* `std::cout` для стандартного потока вывода.  
* `std::cerr`/`std::clog` для стандартного потока ошибок (небуферизованный и буферизированный вывод).

Также предопределены псевдонимы типов для часто используемых потоков (и их аналоги для широких символов вида `std::w<имя>`), имя конструируется из:

* Префикса `i` для потока ввода, `o` для потока вывода или без префикса для потока ввода и вывода,  
* Квалификатора сущности `f` для файлового ввода/вывода, `string` для ввода/вывода в класс строки, `span` для ввода/вывода в буфер,  
* Строки `stream`

Часто встречаемые в интерфейсах типы `std::istream`, `std::ostream` и `std::iostream` используются для определения полиморфных ссылок и указателей на реализации потоков.

##### Работа с ошибками

Потоки поддерживают два вида работы с ошибками: через явную проверку состояния и через исключения.  
Потоки имеют четыре состояния:

* `good()`/`goodbit` \- поток в состоянии продолжать нормальную работу.  
* `bad()`/`badbit` \- поток не в состоянии 	продолжать нормальную работу, его требуется закрыть.  
* `fail()`/`failbit` \- поток встретил ошибку форматирования, но способен продолжать нормальную работу.  
* `eof()`/`eofbit` \- поток встретил конец файла.

Потоки являются *booleany типами* с проверкой `!fail()` эквивалентной значению `true`.  
Используя метод `exceptions()` можно выбрать для каких состояний поток будет бросать исключение (об исключениях поговорим в главе 7).

##### Работа с локалью

Библиотека потокового ввода/вывода продолжает быть зависимой от локали. Однако зависимость эту можно контролировать на уровне каждого объекта потока (метод `imbue()`), а не только глобально, как это было в выводе в стиле С.  
Локали в стандартной библиотеке C++ представлены объектом `std::locale`. С данным объектом связывается набор фацетов, каждый из которых отвечает за действия в одной из следующих категорий:

* Классификация символов (`ctype`)  
* Конверсия кодировок (`codecvt`)  
* Коаллисинг строк (`collate`)  
* Локализация сообщений (`messages`)  
* Форматирование времени (`time_get`/`time_put`)  
* Форматирование чисел (`num_get`/`num_put`)  
* Пунктуация в числах (`numputct`)  
* Форматирование денежных единиц (`money_get`/`money_put`)  
* Пунктуация в денежных единицах (`moneypunct`)

Локаль содержит только один фацет на категорию. Каждый из фацетов можно использовать получив ссылку на него из объекта локали благодаря свободной функции `std::use_facet`.  
Больше примеров хорошо реализованных фацетов можно найти в библиотеке Boost, в под-библиотеке `boost::locale`.

##### Форматирование и стандартные типы с форматированием

Форматирование в данной библиотеке организовано на основании трех аспектов: модификаторы форматирования в объекте потока, локали, перегрузки операторов `operator>>()`/`operator<<()`. Последнее часто называют *форматером типа*.  
Первый аспект изменяется методами экземпляра потока или функции манипуляции вводом/выводом (`iomanip`) которые под капотом также вызывают методы экземпляра потока, второй мы разобрали ранее. Третий аспект может быть реализован на стороне пользователя, что создает точку расширения.  
Так для следующих типов форматеры заданы в стандартной библиотеке:

* Все числовые типы \- числовое форматирование.  
* Тип `bool` \- форматирование как числа или строки.  
* Тип `void*` \- форматирование как значение указателя.  
* Все символьные типы \- посимвольный ввод/вывод.  
* Все строки символьных типов (для ввода, только С массивы таких типов) \- сырой ввод/вывод.  
* Типы потоков и буферов потоков \- передача значений потоков друг в друга.  
* Классы `std::basic_string`, `std::basic_string_view`, `std::bitset`, `std::complex` из стандартной библиотеки.  
* Все классы генераторов псевдослучайных чисел и распределений случайных величин из стандартной библиотеки.

###### Наиболее часто встречаемые манипуляторы ввода/вывода

Стоит отдельно отметить следующие манипуляторы ввода вывода, так как они или являются крайне полезными или часто встречаются:

* `std::boolalpha` \- регулирует отображение типа `bool`.  
* `std::ws` \- используется на потоках ввода и поглощает все, что считается разделителем в текущей локали.  
* `std::flush` \- вызывает сбрасывание буфера потока в нижележащий объект ОС.  
* `std::endl` \- выводит в поток символ новой строки и вызывает `std::flush`.  
* `std::get_time`/`std::put_time` \- позволяет вывести или прочитать штамп времени.  
* `std::get_money`/`std::put_money` \- по аналогии с `std::get_time`/`std::put_time` для денежной единицы.  
* `std::quoted` \- позволяет интеллектуально передавать строки с кавычками в и из потоков используя символы экранирования.  
* `std::unitbuf` \- заставляет поток вызывать `std::flush` после каждой операции вывода.  
* `std::setw` \- устанавливает ширину поля следующей операции вывода.

##### Синхронизированный ввод/вывод

В термин **“синхронизированный”** библиотекой потокового ввода/вывода вкладывается два значения:

1. Два потока могут быть синхронизированы через метод потока `tie()` для того, чтобы ссылаясь на одну и ту же сущность ОС, ввод в один поток был виден в выводе из другого потока сразу. Иначе обычно возникают проблемы с буферизацией.  
2. Вывод в поток может быть синхронизирован многопоточно с использованием обертки над потоком вывода `std::osyncstream` (C++20). Такой вывод не допускает перемежения и гонок данных.

### Шаблоны работы с библиотекой потокового ввода/вывода

#### Построчный ввод

Это часто используемый формат работы с вводом/выводом, когда сначала требуется ввести строку полностью, а затем осуществить ее разбор.  
Для этого в C++ определена функция `std::getline()`. Она осуществляет поиск следующего символа разделителя (по умолчанию \- символа новой строки) и выводит все между разделителями в класс строки стандартной библиотеки C++ `std::basic_string`. Обычно эту функцию зовут в цикле. А так как она осуществляет возврат переданного потока, то ее также можно использовать как выражение для условия цикла, что позволяет пройтись по все строкам в объекте ввода/вывода ОС.

```c++
std::ifstream file{"my_file.txt"};
for (std::string line; std::getline(file, line);) {
  parse(line);
}
```

#### Идиома промежуточного потока

Данная идиома используется для ускорения работы с выводом. Она реализуется в перегрузке `operator<<()` для пользовательского типа данных и подразумевает форматированный вывод в промежуточный объект `std::ostringstream` с последующей передачей буфера данного потока в поток вывода.  
Это делается для сокращения числа операций над буфером потока и объектом ОС, а также для предсказуемой синхронизации вывода. Другим плюсом такого подхода является обнуление состояния модификаторов и локали на новом объекте потока.

```c++
class MyClass {
  friend std::ostream& operator<<(std::ostream& o, const MyClass& c) {
    std::ostringstream intermediate;
    // Форматированный вывод в промежуточный поток
    intermediate << '{' << /* ... */ ;
    return o << intermediate.rdbuf();
  }
};
```

### Критика библиотеки потокового ввода/вывода

Опыт использования библиотеки потокового ввода/вывода показал, что ее дизайн имеет слабые стороны. Таковыми можно считать:

* Зависимость от объекта локали, предотвращающая оптимизации парсинга и сериализации объектов.  
* Запутанная и сложная для расширения иерархия классов. В иерархии содержится очень много виртуальных методов, что ведет к потере производительности ввиду накопления стоимости виртуальных вызовов.  
* Форматированный вывод требует фиксирования в синтаксисе, что часто не является желательным.  
* Состояние модификаторов форматирования и локали переносится в объекте потока, что при большой вложенности форматируемых структур приводит к их постоянному сохранению и восстановлению или к ошибкам форматирования, которые сложно отловить, так как они проявляются только во время исполнения, и легко допустить при кодировании своего форматера.

С некоторыми аспектами работы с потоками может помочь часть библиотеки Boost \- `boost::io`.

## Дополнительные функции форматирования в C++

По историческим причинам в стандартной библиотеке C++ помимо функций форматирования и парсинга произвольных данных накопилось множество имплементаций функций парсинга и форматирования числовых типов данных.

##### Функции форматирования числовых типов, зависимые от локали

К самым ранним относятся функции парсинга в стиле С:

* Функции `std::ato<тип>()`, где тип `f` для `double`, `i` для `int`, `l` для `long`, `ll` для `long long` \- преобразуют нуль-терминированную строку в числовой тип данных.  
* Функции `std::<тип строки>to<тип данных>()`, `<тип строки>` \- `str` для узких строк, `wcs` для широких строк, а `<тип данных>` одно из `l, ll, ul, ull, f, d, ld, imax, umax` \- данные функции отличаются тем, что могут преобразовывать только часть строки, что подходит для парсинга многих значений из строки, и принимают основание системы счисления.

Все функции парсинга в стиле С зависят от текущей глобальной С локали.  
Начиная с C++11 для класса строк `std::basic_string` в стандартной библиотеке были добавлены свободные функции, принимающие класс строки и оборачивающие вызовы функций в стиле С: `std::sto<тип>()`, где `<тип>` \- один из `i, l, ll, ul, ull, f, d, ld`. Так как они вызывают функции в стиле С, то они продолжают быть зависимыми от локали.  
Другим приятным обновлением в C++11 стали функции `std::to_string()`/`std::to_wstring()` для форматирования числовых типов в экземпляры `std::basic_string`. Они также (до C++26) остаются зависимыми от локали, так как под капотом вызывают функции форматирования в стиле С `std::sprintf()`/`std::swprintf()`.  
Также удобным API для конвертирования числовых типов во многих проектах считается часть библиотеки Boost `boost::lexical_cast`.

##### Функции форматирования числовых типов, независимые от локали

Начиная с C++17 настоящей отдушиной для программистов стали функции форматирования и парсинга числовых типов без использования локали `std::to_chars()`/`std::from_cars()`. Помимо основного преимущества данные функции также обладают очень хорошим интерфейсом.

```c++
const size_t buf_size = 10;
char buf[buf_size]{};
std::to_chars_result result = std::to_chars(buf, buf + buf_size, -3.14159, std::chars_format::scientific, 3);

if (result.ec != std::errc()) {
  std::cout << std::make_error_code(result.ec).message() << '\n';
}

float result;
auto [ptr, ec] = std::from_chars(buf, buf + buf_size, result);
```

## Новые принципы форматирования в стандартной библиотеке C++

Со временем большую популярность среди разработчиков приобрела сторонняя библиотека `{fmt}`. Она предоставляла форматирование в стиле таких языков как Python, при этом сохраняя производительность и проверку типов аргументов во время компиляции. Это еще не настолько же удобный инструмент как форматирующие строки, но синтаксис и семантика стали намного более приятными.  
Начиная с C++20 библиотека `{fmt}` была частично перенесена в стандартную библиотеку как библиотека форматирования (formatting library).  
Основными атрибутами дизайна данной стандартной библиотеки можно считать:

* Независимость от локали по умолчанию. Это означает, что если строкой формата явно не задано преобразование, зависимое от локали, то локаль не используется. Это сильно повышает производительность преобразований.  
* Форматирование в буферы. Предоставляется явная функция подсчета  объема памяти, необходимого для вывода, `std::formatted_size()` и три вида функции форматирования:  
  * `std::format()` \- для получения результата в виде стандартного класса строки `std::basic_string`.  
  * `std::format_to()` \- для вывода через абстракцию итератора в расширяемый контейнер.  
  * `std::format_to_n()` \- для вывода через абстракцию итератора в ограниченный по объему контейнер.  
* Соответствие строки формата и аргументов функции проверяется во время компиляции с выводом понятных ошибок. С C++26 добавляется возможность изменять строку формата в рантайме.  
* Точка расширения форматирования оформлена в виде специализации шаблона класса `std::formatter` c двумя методами:  
  * Метод проверки формата для данного класса `parse()`. Данный метод может быть вызван во время компиляции.  
  * Метод форматирования для экземпляра данного класса `format()`  
* Следующие типы стандартной библиотеки получили свои форматеры:  
  * Сырые строки, числовые типы, знаковые типы и из массивы, типы указателей и булевый тип.  
  * Типы времени и календаря из стандартной библиотеки `std::chrono`.  
  * Типы стектрейса, пар и кортежей, промежутков, оберток контейнеров и пути до файла.  
* Возможность использовать буферизированный вывод в потоки или файлы или прямой, основываясь на специализации шаблона `std::enable_nonlocking_formatter_optimization` для конкретного форматируемого в данный момент класса.  
* Управление используемой локалью осуществляется явно через аргумент функции форматирования.

```c++
std::format("My name is {} and my favorite number is {}", name, num);
// My name is John and my favorite number is 42
std::format("My name is {1} and my favorite number is {0}", num, name);
// My name is John and my favorite number is 42
std::format("My name is {1:.2s} and pi is {0:.2f}", 3.14159, name);
// My name is Jo and pi is 3.14
```

Данна библиотеку очень хорошо показала себя на практике в основном за счет интуитивно понятного и легкого, для перехода с других языков программирования, синтаксиса строк форматирования и хорошего дизайна интерфейса расширения для пользовательских типов.  
Альтернативами данной стандартной библиотеке остаются:

* Оригинальная библиотека `{fmt}`, которая продолжает развиваться вне цикла релиза стандарта C++.  
* Часть библиотеки Boost `boost::format`, которая предлагает свой набор компромиссов.

##### Простой форматированный вывод

Начиная с C++23 мы получили простую форму форматированного вывода в виде функций `std::print()`/`std::println()`, поддерживающих новые принципы форматирования. Данные функции выводят форматированную строку в стандартный поток вывода или же в произвольный поток, передаваемый первым аргументом.

```c++
std::print("{2} {1}{O}!\n", 23, "C++", "Hello");
// Hello C++ 23!
std::FILE* stream{std::fopen("test.txt", "w")};
std::print(stream, "File: {}", "Hello");
// test.txt << "File: Hello”
```

## Платформенный ввод/вывод

Иногда, в целях повышения производительности приложения, стоит использовать функции ввода/вывода, предоставляемые платформой или ОС. Документацию по платформенному вводу выводу можно найти:

* Для POSIX/Linux: [https\://man7.org/linux/man-pages/man2/open.2.html](https://man7.org/linux/man-pages/man2/open.2.html)  
* Для Windows: [https\://learn.microsoft.com/en-us/windows/win32/api/fileapi/](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/)  

### Основания для использования платформенного ввода/вывода

#### Проблема производительности при двойной и более буферизации

Данная проблема возникает из\-за слишком большого количества слоев абстракций между программным кодом и устройством ввода/вывода. На каждом слое может находиться свой буфер обмена для “увеличения производительности”, но их совместная работа уже вызывает неожиданные эффекты и выбросы по скорости чтения/записи данных. Примером такого слоистого пирога может служить:

1. Буфер в стандартной библиотеке C++.  
2. Буфер в платформенном С рантайме.  
3. Буфер, связанный с дескриптором файла в ядре ОС.  
4. Буфер операций файловой системы в ядре ОС.  
5. Буфер операций блочного устройства в ядре ОС.  
6. Буфер записи/чтения жесткого диска.

Используя напрямую системные вызовы или их минимальные обертки, предоставляемые системными библиотеками, можно избавится от буферизации в пространстве пользователя. Использование интерфейса ОС также позволяет избавиться и от других слоев буферизации внутри ядра ОС, например с использованием флагов `O_DIRECT` или `O_SYNC` в Linux POSIX при открытии файла системным вызовом `open()`.

#### Проблемы производительности на стыке пространства пользователя и ядра ОС

В некоторых случаях требуется большая скорость чтения файлов. Стандартным подходом будет вызывать последовательно операции чтения друг за другом, предоставляя буфер определенного размера в пространстве пользователя. Данный подход накапливает накладные расходы на системные вызовы и копирование данных из буфера ядра ОС в буфер в пространстве пользователя, которые со временем становятся проблемой производительности.  
Для решения такой проблемы был предложен механизм отражения (мапирования) файлов в пространство пользователя (POSIX: `mmap()` / Windows: `CreateFileMapping()` \+ `MapViewOfFile()`). Данный механизм позволяет ядру ОС сразу писать данные из файла в память пространства пользователя, минуя внутренний буфер, а пространству пользователя \- обращаться с файлом как просто с непрерывным регионом памяти, операции чтения записи на котором будут организованы прозрачно с точки зрения кода пользователя.

#### Неблокирующие запись/чтение

Стандартная библиотека C++ и стандартная библиотека С не касаются такого очень популярного аспекта работы с файлами и другими объектами ввода/вывода ОС как неблокирующий и асинхронный ввод/вывод.  
Такая возможность поддерживается на всех больших платформах и состоит она в том, что платформа предоставляет интерфейс для постановки задач на ввод/вывод объекту и проверки какие из объектов в данный момент готовы для постановки новых задач. Тем самым при массовом обращении к объектам ввода/вывода ОС удается экономить очень большое количество системных вызовов, тем самым сильно повышая производительность. Также у пространства пользователя появляется возможность не блокировать поток, занятый вводом/выводом, а также утилизировать его для других задач пока ОС производит ввод/вывод асинхронно.  
Следующие функции организуют механизмы асинхронного ввода/вывода:

* Для Linux POSIX:  
  * Создание асинхронных дескрипторов: [open()](https://man7.org/linux/man-pages/man2/open.2.html) и флаги `O_NONBLOCK`, `O_NDELAY`  
  * Проверка результатов операций: [poll()](https://man7.org/linux/man-pages/man2/poll.2.html), [select()](https://man7.org/linux/man-pages/man2/select.2.html) и [epoll()](https://man7.org/linux/man-pages/man7/epoll.7.html)  
* В Windows существует несколько конкурирующих систем асинхронного и неблокирующего ввода/вывода. Примерами могут служить:  
  * [Overlapped I/O](https://learn.microsoft.com/en-us/windows/win32/sync/synchronization-and-overlapped-input-and-output?redirectedfrom=MSDN)  
  * [I/O Completion Ports](https://learn.microsoft.com/en-us/windows/win32/fileio/i-o-completion-ports?redirectedfrom=MSDN)

Для других POSIX систем требуется смотреть документацию конкретной системы, так как даже в Linux существуют дополнительные механизмы асинхронного ввода/вывода, такие как [`io_uring`](https://man7.org/linux/man-pages/man7/io_uring.7.html).
